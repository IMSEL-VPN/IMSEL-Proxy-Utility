# Управление приложением

Полная спецификация управления приложением IMSEL VPN через подписку — по схеме, совместимой с большинством известных клиентов. Клиент читает HTTP-заголовки ответа подписки и fallback-строки `#param` в теле и применяет их к настройкам и поведению.

Параметры действуют при ручном и автоматическом обновлении подписки. Этот справочник — единственный источник описания команд для администраторов подписок.

## Как отправляет запросы клиент

| Заголовок запроса | Значение |
| --- | --- |
| `User-Agent` | `IMSEL/<версия>/<ОС>/<hwid>` — например, `IMSEL/1.0.0/Android/17839452147361875676` (может быть подменён командой `change-user-agent`; до инициализации используется стандартное fallback-значение для совместимости с панелями) |
| `X-HWID` | идентификатор устройства — отправляется **всегда**, отключения нет |
| `Cookie` | тот же идентификатор устройства (HWID), что и в `X-HWID` — дублирование, как в других популярных клиентах (`cookie: <hwid>`) |
| `x-device-locale` | язык устройства (`ru`, `en`, …) |
| `x-device-os` | платформа (`Android`, `Windows`) |
| `x-ver-os` | версия ОС (`14`, `10.0.22631`, …) |
| `x-device-model` | модель устройства (`23117RA68G`, имя ПК на Windows; пустая — заголовок не отправляется) |
| `Accept` / `Connection` | `*/*` / `close` |

`change-user-agent` заменяет только User-Agent — заголовки `x-device-*` и `X-HWID` продолжают отправляться. Domain Fronting подписочных URL — см. [Подписка через домен-фронтинг](domain-fronting.md).

## Способы передачи параметров

**1. HTTP-заголовок ответа (приоритетный):**

```http
HTTP/1.1 200 OK
profile-title: IMSEL Node
profile-update-interval: 12
```

**2. Строка в теле подписки (fallback):**

```text
#profile-title: IMSEL Node
#profile-update-interval: 12
vless://...
```

Правила:

- **Приоритет:** HTTP-заголовки выше команд тела. Обычные немаркированные строки не считаются командами; отдельные ссылки профиля маршрутизации распознаются в любой строке смешанного списка, как описано ниже.
- **Boolean:** только `true`/`1` → включить и `false`/`0` → выключить; регистр и пробелы по краям не важны. Отсутствующее, пустое или некорректное значение сохраняет прежний выбор. Например, `yes` не означает ни включение, ни выключение.
- **Кодирование:** `base64:` (UTF-8) используйте только для текстовых параметров, где это явно указано; числовые, boolean и JSON-списки передаются без этого префикса.
- Для основных метаданных поддерживаются совместимые имена без дефисов (`#profile-title:` и `#profiletitle:`). Для значений настроек и замков используйте точные имена с дефисами из таблиц, например `#subscription-lock-auto-ping:`.
- Поддерживаемые команды применяются при каждом успешном обновлении подписки. Блокировка пользовательского редактирования не запрещает провайдеру обновлять её значения. Команды не предоставляют согласие на небезопасный TLS и применение настроек к готовому JSON.
- URL-значения для веб-адресов принимаются только со схемой `http://`/`https://` (включая фронтинг-URL); невалидные значения молча отбрасываются. Ссылка профиля в `routing` имеет отдельный формат, описанный ниже.

## Данные подписки

### Имя подписки

```http
profile-title: IMSEL Node
profile-title: base64:SU1TRUwgTm9kZQ==
```

До 25 символов (обрезается). В base64-варианте первая строка — имя, остальные — описание. Альтернативные заголовки: `subscription-name`, `content-disposition` (также распознаётся из заголовка-строки).

### Описание подписки

```http
profile-description: Премиум сервера IMSEL
profile-description: base64:0J/RgNC10LzQuNGF0Lwg0YHQtdGA0LLQtdGA0LAgSU1TRUw=
```

Показывается мелким текстом в шапке карточки. Имеет приоритет над описанием из base64-`profile-title`.

### Статус (трафик и срок)

```http
subscription-userinfo: upload=1073741824;download=10737418240;total=107374182400;expire=1700000000
```

Трафик в байтах. `expire` — unix-время в секундах; значения **больше 32 000 000 000 трактуются как миллисекунды** и конвертируются. `total=0` — безлимит (∞). Прогресс-бар: зелёный → оранжевый (≥70%) → красный (≥90%).

### Интервал автообновления

```http
profile-update-interval: 6
```

Часы. `> 0` — включить автообновление с этим интервалом (ограничивается диапазоном **1–168 ч**); `0` — выключить; отсутствие — не управлять. Интервал применяется и к фоновым задачам автообновления.

### Ссылки

```http
support-url: https://t.me/imsel_support
profile-web-page-url: https://imsel.dev
premium-url: https://imsel.dev/premium
```

Кнопки в карточке подписки: поддержка (✈), веб-страница (ℹ), «Премиум» (★, только при наличии `premium-url`).

### Объявление

```http
announce: [текст | base64:...]
announce-url: https://imsel.dev/announcement.txt
```

Текст объявления (до 200 символов, обрезается с «…») в рамке в карточке. `announce` (текст напрямую) имеет приоритет над `announce-url`: клиент скачивает текст по ссылке (тело — plain или `base64:...`, тот же таймаут и User-Agent, ошибки молча игнорируются). Устаревший `sub-info` (текст) работает как alias `announce`.

### Сортировка серверов

```http
subscriptions-sort-type: [without | ping | alphabet]
```

Собственное расширение IMSEL: сортировка серверов внутри подписки.

## Зеркала подписки

Первый URL — без метки, каждый следующий — с меткой `url:N=`, в конце может стоять `fallback-url=`:

```text
https://cdn.imsel.dev/sub/token#m1?resolve-address=cdn.imsel.dev&host=backend.imsel-api.com
  |url:1=https://fallback.imsel.dev/sub/token#m2?resolve-address=fallback.imsel.dev&host=backend.imsel-api.com
  |url:2=https://route.imsel.dev/sub/token#m3?resolve-address=route.imsel.dev&host=backend.imsel-api.com
  |fallback-url=https://backup.imsel.dev/token
```

- **Позиции:** первый URL = позиция `0`, `url:1` = второй URL (позиция `1`), `url:N` = позиция `N`. Диапазон меток: 0–99.
- Разделители: `|` или перевод строки.
- Каждый URL — обычный или [фронтинг-URL](domain-fronting.md).
- Немаркированный список (просто URL через `|`/`\n`) тоже принимается — зеркала по порядку.
- Зеркала пробуются по порядку до первого успешного ответа; во время загрузки top-баннер показывает позицию (`2/4`) и секунды до таймаута.
- Если CDN вернул пустое тело с `HTTP 200` без данных о подписке и команд, приложение пробует следующий адрес. Непустой ответ неправильного формата не запускает такой переход.

## Управление подпиской

### Смена URL (new-url)

Три режима работы по значению:

```http
new-url: https://node1.imsel.dev/token
```

Одиночный URL — замена **только первого зеркала** (позиция 0), остальные не трогаются.

```http
new-url: https://a.imsel.dev/token|https://b.imsel.dev/token|https://c.imsel.dev/token
```

Несколько plain URL без меток — полная замена списка (легаси-режим).

```http
new-url: https://primary.imsel.dev/t|url:1=https://secondary.imsel.dev/t|fallback-url=https://reserve.imsel.dev/t
```

Помеченная структура — точечно по позициям: упомянутые позиции заменяются, `fallback-url=` записывается в поле запасного адреса, **неупомянутые зеркала не меняются**. Все URL проходят валидацию схемы; невалидные части отбрасываются.

Применяется начиная со следующего обновления.

### Точечные операции с зеркалами (new-url-N)

Заголовок `new-url-N` (N — позиция: `0` — первый URL, `1` — `url:1`, …) или телесная строка `#new-url:N=значение` (колон-форма; при нескольких командах используйте каноническую форму с дефисом — одноимённые `#new-url:` строки перекрывают друг друга):

| Команда | Действие |
| --- | --- |
| `new-url-1: https://mirror.imsel.dev/tok#m?resolve-address=mirror.imsel.dev&host=backend.imsel-api.com` | заменить зеркало `url:1` целиком |
| `new-url-3: https://append.imsel.dev/token` | N = количество зеркал → добавить в конец |
| `new-url-1: 0` (или `false`) | удалить зеркало `url:1` |
| `new-url-1: resolve-address=198.51.100.15` | точечно заменить только `resolve-address` — домен **или IP-адрес** |
| `new-url-0: host=backend.imsel-api.com` | точечно заменить только `host` (Host-заголовок фронтинга) |

Правила:

- Патч параметра: существующее значение заменяется, отсутствующее — дописывается в фрагмент URL.
- N > количества зеркал («дыра») игнорируется.
- Операция, после которой список опустел бы полностью, отклоняется целиком.
- Порядок применения в одном ответе: `new-url` → точечные замены/удаления → патчи параметров → домены.

### Смена домена (new-domain)

```http
new-domain: new-api.imsel.dev
new-domain-1: mirror.imsel.dev
new-domain: 1=mirror.imsel.dev
```

`new-domain` — заменяет основной домен (authority) в URL во **всех** зеркалах. `new-domain-N` / колон-форма — меняет домен только у зеркала на позиции N. Путь, параметры и метки (query/fragment) сохраняются.

**Как работает `new-domain` с домен-фронтингом (умная синхронизация):**
Команда `new-domain` предназначена **только для смены домена-фронта** и работает так, чтобы не сломать ваше подключение:

* **Сценарий 1 (Стандартный фронтинг):** Допустим, URL был `https://old.com/tok#m?resolve-address=old.com&host=backend.com`.
  Приходит команда `new-domain: new.com`.
  Приложение видит, что `resolve-address` совпадал со старым доменом (`old.com`), и меняет их синхронно.
  *Результат:* `https://new.com/tok#m?resolve-address=new.com&host=backend.com`. (Фронт изменён, настоящий `host` не тронут).

* **Сценарий 2 (Указан IP):** Допустим, URL был `https://old.com/tok#m?resolve-address=1.1.1.1&host=backend.com`.
  Приходит команда `new-domain: new.com`.
  Приложение видит, что `resolve-address` — это IP, а не `old.com`, поэтому оставляет его как есть.
  *Результат:* `https://new.com/tok#m?resolve-address=1.1.1.1&host=backend.com`.

**Как поменять ТОЛЬКО параметр `host=`?**
Команда `new-domain` **никогда** не меняет параметр `host=` (настоящий сервер назначения для CDN). Если провайдеру нужно изменить именно `host`, используется точечная команда `new-url-N` (см. пункт выше):
```http
new-url-0: host=new-backend.com
```

### Запасные адреса (fallback-url)

```http
fallback-url: https://standby.imsel.dev/token
fallback-url: https://f1.imsel.dev/token#m?resolve-address=f1.imsel.dev&host=backend.imsel-api.com|https://f2.imsel.dev/token
```

Пробуются **по очереди после отказа всех зеркал**, включая таймауты и пустые CDN-ответы без данных о подписке. Таймаут задаётся в настройках подписки или приложения. Несколько URL через `|`/`\n`; фронтинг-URL разрешены. Встроенный `fallback-url=` в конце помеченного списка имеет тот же эффект и пробуется первым. Fallback не заменяет список зеркал.

### User-Agent (change-user-agent)

```http
change-user-agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
```

Подменяет User-Agent для **всех** запросов этой подписки: зеркала, fallback и скачивание `announce-url`. Применяется начиная со следующего обновления.

### Точечная и общая блокировка настроек

Значение настройки и разрешение пользователю менять его задаются **независимо**. Например, включённый автопинг может быть заблокирован, а выключенный оставаться доступным для редактирования.

```http
subscription-auto-ping-enable: 1
subscription-lock-auto-ping: 1
subscription-lock-fetch-timeout: true
```

`subscription-lock-<id>: 1` запрещает редактирование одной настройки. `0` снимает только этот точечный замок. Вместо `1/0` принимаются `true/false`. Допустимые `<id>` перечислены полностью в таблице ниже; произвольные имена не поддерживаются.

```http
subscription-settings-lock: 1
subscription-lock-auto-ping: 0
```

`subscription-settings-lock: 1` блокирует все доступные провайдеру настройки **только этой подписки**, а не приложение и не соседние подписки. В примере точечное `0` не открывает автопинг, пока действует общий замок.

Правила сохранения и снятия:

- Отсутствующая, пустая или некорректная команда не меняет сохранённое значение или замок. Прекратить отправку заголовка недостаточно для разблокировки.
- `subscription-settings-lock: 0` снимает только общий замок; сохранённые точечные замки остаются. Для их снятия нужны соответствующие `subscription-lock-<id>: 0`.
- Точечное снятие не отменяет общий замок, режим защиты `hide-settings`, ручную блокировку или ограничения автора раздачи.
- HTTP-заголовок приоритетнее одноимённой строки `#param` в теле. Если заголовок некорректен, команда тела не заменяет его, а прежнее состояние сохраняется.
- Значения и замки сохраняются после перезапуска. Получение команды для подписки A не меняет подписку B. Обновление без команды также не переносит выбор из другой подписки.
- Новые замки ограничивают редактирование, но сами по себе не скрывают конфиги, не запрещают раздачу и не включают маскировку URL. Для защиты приватности используется отдельный `hide-settings`.

Чтобы открыть автопинг после приведённого примера, отправьте оба снятия:

```http
subscription-settings-lock: 0
subscription-lock-auto-ping: 0
```

Те же команды допустимы в теле как `#subscription-settings-lock: 0` и `#subscription-lock-auto-ping: 0`.

#### Полный список точечных замков и заголовков значений

Для каждого из **47 ID** ниже имя замка имеет вид **`subscription-lock-<id>`**. Все замки принимают `1/0` или `true/false`. В колонке значений приведены фактические имена: одинаковое окончание ID **не означает**, что существует заголовок `subscription-<id>`. Старые имена сохраняются; например, значение `ping-type` и его замок `subscription-lock-ping-type` имеют разные префиксы.

`bool` в таблице означает строгие `1/0` или `true/false`. Если значение нельзя задать заголовком, его замок всё равно поддерживается и фиксирует уже выбранное пользователем значение. Отдельная блокировка имени не является командой переименования; не отправляйте `subscription-name` в расчёте переименовать уже сохранённую группу.

| `url` | URL и зеркала | `new-url`, `new-url-N`, `new-domain`, `new-domain-N`, `fallback-url` | Форматы и ограничения из раздела управления зеркалами; не `subscription-url` |

```http
subscription-sniffing-dest-override: ["http","tls"]
subscription-sniffing-domains-excluded: ["example.org","regexp:^(.+\\.)?example\\.org$"]
subscription-lock-sniffing-dest-override: 1
```

Списки не включают JSON-разрешение автоматически; `[]` отличается от отсутствующего заголовка. Ограничения Sniffing и JSON описаны в [руководстве по настройкам группы](../faq/getting-started.md#6-сниффинг-и-списки-для-одной-группы).

#### Три исключения из блокировки провайдером

Эти значения провайдер может задавать, но не может запретить пользователю менять их ни точечным, ни общим замком, ни через `hide-settings`:

| Настройка | Заголовок значения | Значения | Неподдерживаемый ID замка |
| --- | --- | --- | --- |
| Сортировка серверов | `subscriptions-sort-type` | `without`, `ping`, `alphabet`; некорректное значение сохраняет прежнюю сортировку | `sort-type` |
| Скрытие подписки с главного экрана | `subscription-hidden` | bool; не сворачивание списка серверов | `hidden` |
| Уведомления об обновлении | `subscription-update-notifications` | bool | `update-notifications` |

Например, `subscription-lock-sort-type: 1` и `subscription-lock-hidden: 1` игнорируются. **Ручная блокировка пользователя и ограничения автора раздачи сохраняются и для этих настроек.** Единственную подписку пользователь скрыть не может, чтобы главный экран не остался пустым. Уведомления об истечении не являются исключением: для них поддерживается `subscription-lock-notify-expire`. Сворачивание списка также не является исключением: для него поддерживается `subscription-lock-server-list-collapse`.

#### Как это видно пользователю

В окне управления сначала расположены шапка, URL с маскировкой и действия, затем остальные настройки. У заблокированного переключателя вместо неактивного тумблера показаны текущее **«Включено» / «Выключено»** и замок; у других полей доступно текущее значение. Нажатие на замок объясняет причину: провайдер, ручная блокировка или автор раздачи. Общий баннер не заменяет состояние каждой настройки.

«Скрыт с главного» расположен непосредственно под разрешением сворачивать список серверов. Если сворачивание выключено и заблокировано провайдером, пользователь может скрыть всю подписку, когда скрытие доступно. Это не снимает замок сворачивания.

Показанное значение и причина отражают **текущее состояние**, а не историю полученных команд. Замок сам по себе не включает и не выключает настройку. После снятия замка прежнее значение остаётся, пока его не изменит пользователь или новая корректная команда. В старых описаниях автоподключение при запуске могло считаться всегда доступным: теперь и оно, и способ выбора сервера допускают точечный и общий замок; уведомления об обновлении, напротив, входят в три исключения выше.

### Режим защиты приватности (hide-settings)

```http
hide-settings: 1
hide-settings: 0
```

`hide-settings: 1` включает **режим защиты подписки** (снимается только `hide-settings: 0`, пользователь не может разблокировать вручную):

1. **Блокировка настроек** — только для чтения, кроме трёх исключений провайдера выше. Сюда входят и автоподключение при запуске, и выбор сервера. Ручная разблокировка не снимает защиту провайдера.
2. **Запрет раздачи** — кнопка «Поделиться» и пункт меню скрыты: нельзя создать offline-раздачу (snapshot раздаёт конфиги, URL-режим — сам URL).
3. **Защита отображения адреса подписки** — маскировка URL включается принудительно; это не шифрование сетевого запроса. Выключить маскировку при этом замке нельзя.
4. **Ограничение подробности журнала** — при замке используется уровень `warning`, чтобы не показывать адреса в подробной диагностике.
5. **Конфиги серверов скрыты** (кнопки ℹ и «Поделиться QR») — обычная двойная проверка при замке не проходит; исключение просмотра конкретного сервера описано ниже и не снимает замок редактирования.

`hide-settings: 0` снимает только этот режим защиты. Настройки становятся доступными, если не действуют другие замки; раздача разрешена, если нет отдельных ограничений автора. Маскировка URL остаётся включённой. При отсутствии других защищённых подписок подробность журнала возвращается к пользовательскому выбору.

Ручная блокировка пользователем является отдельным состоянием и действует также на три исключения провайдера. Она не снимается заголовками. Ограничения автора раздачи также не отменяются командами подписки.

**Видимость конфигураций серверов** (кнопки «Конфиг сервера» ℹ и «Поделиться QR» на строках серверов). По умолчанию для панельных подписок (с URL) кнопки **скрыты** — строгая двойная проверка открывает их только при одновременном выполнении:
   - **Проверка 1 (серверная):** панель явно прислала `hide-settings: 0` в **последнем успешном обновлении** — активное разрешение, которое истекает, если панель перестала присылать команду;
   - **Проверка 2 (локальная):** подписка не заблокирована и раздача, из которой она создана, не включала «скрыть конфиги».

   Всегда видимы (проверки не требуются): ручные серверы, импорт из буфера, подписки из раздачи без «скрыть конфиги».

**Per-server исключение — маркер в имени сервера.** Для отладки/удобства настройки панели можно открыть конфиг конкретного сервера, добавив маркер в его имя (remark):

```text
vless://uuid@server:443#user1 [server-setting-hide-false]
```

Сервер с маркером `[server-setting-hide-false]` (регистронезависим, положение в имени любое) разрешает просмотр конкретного сервера без обычной двойной проверки подписки. Экспорт по QR по-прежнему зависит от разрешения раздачи, а ограничение автора «скрыть конфиги» запрещает просмотр и с маркером. Маркер автоматически вырезается из отображаемого имени (пользователь видит просто `user1`). Работает для share-ссылок и JSON-подписок (`remarks`); снимается удалением маркера из имени при следующем обновлении.

Право просмотра и право редактирования различаются: маркер открывает просмотр,
но **не снимает** ручную блокировку или блокировку редактирования провайдером.
Ограничение автора раздачи «скрыть конфиги» также сохраняется.

Разрешения действуют и для уже открытого редактора. Если успешное обновление
отзывает просмотр, конфигурация скрывается сразу, а сохранение недоступно.
Например, после ответа с `hide-settings: 0` следующий успешный ответ без этого
разрешения закрывает просмотр, если нет действующего исключения конкретного
сервера. При удалении сервера или замене его исходной конфигурации старые
правки не записываются поверх новой версии: откройте актуальный сервер заново.
Автоматического сохранения при отзыве разрешения нет.

Разрешённые незаблокированные конфигурации URL-подписок, ручные серверы и
локальные группы остаются редактируемыми: общего запрета редактирования нет.
Ручной замок такой группы запрещает изменения, но сам по себе не скрывает
разрешённый просмотр конфигурации.

### Безопасность скачивания

При недоверенном HTTPS-сертификате приложение предлагает отменить загрузку, разрешить одну попытку или разрешить этот сервер. Постоянное разрешение относится к конкретному TLS-адресу, порту и сертификату; новый адрес или другой недоверенный сертификат требует нового подтверждения. В фоне неизвестный сертификат не разрешается автоматически.

Параметр `insecure=1` в ссылке — явное исключение проверки для этой ссылки, не для остальных зеркал. Заголовок ответа `insecure: 1` не предоставляет такое разрешение. Используйте исключение только если доверяете владельцу сервера: данные могут быть перехвачены или подменены. Разрешение сертификата не отменяет запрет обращения к локальным и служебным адресам.

### Уведомления о загрузке

Клиент детально сообщает о попытках:

- **Всё упало** — красное уведомление с полной сводкой: `Ошибка: не удалось загрузить подписку. Попытки: зеркало 1 (cdn.imsel.dev): HTTP 502; зеркало 2 (fallback.imsel.dev): таймаут 15 с; запасной URL (backup.imsel.dev): HTTP 404.` Для тотального таймаута добавляется подсказка увеличить таймаут.
- **Успех через отказоустойчивость** — предупреждение: `Подписка обновлена через запасной URL. Недоступны: зеркало 1 (cdn.imsel.dev): таймаут 15 с` или `Подписка обновлена (не все зеркала доступны: …)`.
- Чистый успех — без уведомлений (только top-баннер прогресса).

## Расширенные объявления

### Инфо-блок sub-info

```http
sub-info-color: red
sub-info-text: Продлите подписку со скидкой
sub-info-button-text: Купить
sub-info-button-link: https://imsel.dev/buy
```

Цветной баннер в карточке. Цвет: `red` / `blue` / `green` (default `blue`; неизвестные значения → blue). Текст — до 200 символов (обрезается с «…»), кнопка — до 25. Кнопка не показывается без ссылки. Отключение: `sub-info-text: 0`. Блок скрывается, пока активен баннер истечения (см. ниже).

Цвет сохраняет смысл в светлой и тёмной теме: красный обозначает предупреждение,
синий информационное сообщение, зелёный положительный статус. Оттенки фона,
текста и кнопки подстраиваются под тему для читаемости; выбранный цвет не
заменяется основным цветом оформления приложения.

### Баннер истечения sub-expire

```http
sub-expire: 1
sub-expire-button-link: https://imsel.dev/renew
```

Системный баннер по параметру `expire` из `subscription-userinfo`: за ≤ 3 дней — «Ваша подписка заканчивается через N д.» (или «…сегодня»), после истечения — «Подписка закончилась!». Кнопка «Продлить» открывает ссылку. Имеет приоритет над sub-info-блоком.

### Локальные уведомления об истечении (notification-subs-expire)

```http
notification-subs-expire: 1
```

Локальное уведомление раз в день в течение 3 дней до истечения: «У вашей подписки [имя] скоро истечёт срок действия (через N д.), не забудьте продлить её».

## Настройки подключения (серверные)

Перезаписывают соответствующие настройки карточки подписки и действуют только на её серверы.

### Фрагментация TLS

```http
fragmentation-enable: 1
fragmentation-packets: tlshello
fragmentation-length: 10-30
fragmentation-interval: 10-30
```

`packets`: `tlshello` / `1` / `1-3` / `all`; `length`/`interval`: диапазон `min-max` (положительные целые, min ≤ max). Некорректные значения молча отбрасываются (параметр не применяется).

### Шумовые пакеты

```http
noises-enable: 1
noises-type: rand
noises-packet: 10-20
noises-delay: 10-50
```

Тип шума: `rand` / `str` / `hex` / `base64`. Принимаются оба написания — `noises-type` и `noises-packet-type`; значение `array` трактуется как `rand`. `delay` — диапазон `min-max` мс.

### DoH-резолв адреса сервера

```http
server-address-resolve-enable: 1
server-address-resolve-dns-domain: https://cloudflare-dns.com/dns-query
server-address-resolve-dns-ip: 1.1.1.1
```

Перед подключением домен сервера резолвится через DNS-over-HTTPS (JSON API, A-записи):

- при нескольких A-записях выбирается IP с минимальным временем TCP-подключения (до 5 кандидатов);
- определение IP не меняет имя сервера, указанное для проверки защищённого соединения;
- `dns-ip` — bootstrap: прямое подключение к IP DoH-сервера с подменённым Host, если домен DoH не резолвится;
- по умолчанию (без `dns-domain`) используется `https://common.dot.dns.yandex.net/dns-query`;
- работает для share-ссылок (включая vmess-base64); готовые JSON-конфиги не переписываются;
- ошибка резолва не блокирует подключение — используется исходный домен.

## Область действия команд

Настройки подключения, зеркала, объявления, значения и замки относятся к той подписке, которая прислала команды. Серверы и настройки других подписок не меняются.

`subscription-settings-lock` означает общий замок **одной подписки**, а не глобальную настройку приложения. `subscriptions-collapse` также относится только к обновляемой подписке и не меняет общий переключатель приложения. Профиль маршрутизации группы выбирается отдельно от профиля приложения.

Локальные группы имеют собственные доступные настройки карточки. Массового автопинга при импорте в них нет. Для готовых JSON-конфигураций действуют ограничения из [отдельного справочника](../docs/json-configurations.md): заголовки не включают разрешения применять к ним настройки.

## Поведение приложения

### Предложение профиля маршрутизации

Провайдер может передать определение профиля маршрутизации при обновлении своей подписки. Оно автоматически создаёт или обновляет отдельный профиль этой подписки, **без дополнительного запроса подтверждения**. Форма `onadd` или ссылка без команды также назначает его этой подписке; форма `add` только добавляет или обновляет профиль. Явная команда выбора профиля имеет приоритет над автоматическим назначением. Настройки других подписок и выбранный профиль приложения не меняются. Передайте ссылку профиля в HTTP-заголовке ответа:

```http
routing: imsel://routing/onadd/<base64-профиль>
```

Либо поместите ту же ссылку отдельной строкой в любое место тела подписки:

```text
#announce: Новости подписки
vless://...
imsel://routing/onadd/<base64-профиль>
```

Если заголовок `routing` содержит ссылку профиля, он имеет приоритет над ссылкой в теле. Это передача определения профиля, а не переключатель `routing: 1/0`.

Другой способ передать определение: `subscription-routing-profile-add` (совместимые имена `routing-profile-add` и `routing`). Значением может быть JSON профиля, его Base64-представление с префиксом `base64:` или без него либо ссылка профиля. Например:

```http
subscription-routing-profile-add: imsel://routing/onadd/<base64-профиль>
```

Если соответствующего HTTP-заголовка нет, определение можно передать командой тела:

```text
#subscription-routing-profile-add: imsel://routing/onadd/<base64-профиль>
vless://...
```

HTTP-заголовки приоритетнее команд тела. Отдельная ссылка без `#` и команда
`#subscription-routing-profile-add:` могут находиться после объявления или
серверов. Это работает для обычного текста и Base64-кодированного смешанного
списка. Явная команда `#param` имеет приоритет над отдельной ссылкой без `#`
независимо от положения. Среди явных определений одного источника используется
первое по порядку; более поздняя строка не заменяет его. Сначала выбирается
определение HTTP-источника, и только при его отсутствии используется тело.
Некорректное выбранное определение не заменяется более поздним или определением
из источника с меньшим приоритетом. Строки профиля не добавляются как серверы.

Профиль отображается как `Название профиля [текущее имя подписки]`. Переименование подписки обновляет подпись, но не создаёт другой профиль. Одинаковые названия у разных подписок не объединяют их профили. Если при следующем обновлении определения нет, прежний профиль сохраняется.

Такой профиль доступен только для просмотра: его нельзя вручную редактировать, удалять, клонировать или экспортировать. Отдельное исключение: пользователь может задать локальный интервал геобаз, если настройки подписки и выбор профиля маршрутизации не заблокированы; это не открывает редактирование правил. Назначить его можно только подписке, от которой он получен: не соседней подписке, не всему приложению и не сборке соединения. Удаление подписки или сброс подписок удаляет принадлежащий ей профиль и загруженные для него геобазы, не удаляя самостоятельные профили пользователя и общие геобазы.

Выбор уже существующего пользовательского профиля через `subscription-routing-profile` или `routing-profile` не делает его собственностью подписки. Старые самостоятельные профили также не присваиваются подписке по совпадению имени и не удаляются вместе с ней; новое определение создаёт отдельный профиль подписки. Для подготовки ссылки можно экспортировать свой редактируемый профиль; полученный от подписки профиль экспортировать нельзя. Подробнее: [профили маршрутизации](../faq/routing-profiles.md).

Локальный импорт смешанного текста из буфера или файла не создаёт профиль
провайдера. Дополнительные поддерживаемые настройки требуют подтверждения;
подтверждённый профиль становится самостоятельным пользовательским профилем,
а не собственностью подписки. Импорт сам по себе не включает VPN и не меняет
глобальные настройки. Подробнее: [локальный импорт](../faq/getting-started.md#локальный-импорт-с-настройками).

Для ссылки `imsel://routing/...` поддерживаются формы без команды и с `add` или `onadd` перед данными профиля:

```text
imsel://routing/<base64>
imsel://routing/add/<base64>
imsel://routing/onadd/<base64>
```

`<base64>` — JSON профиля маршрутизации в Base64. Все три формы и ранее созданные ссылки остаются действительными. Поля DNS и полных правил описаны в [формате профиля](../faq/routing-profiles.md#поля-json-профиля). Эти ссылки не являются командами выключения маршрутизации или очистки правил.

При вставке, импорте из буфера обмена или сканировании QR-кода также принимаются ссылки `<scheme>://routing/<base64>`, `<scheme>://routing/add/<base64>` и `<scheme>://routing/onadd/<base64>` с любой схемой, кроме `http` и `https`. Адресная часть должна быть `routing`. Это совместимость формата импорта, а не автоматическое открытие приложения: система открывает IMSEL VPN только по `imsel://`.

Сторонние ссылки копируйте и импортируйте через меню → Импорт из буфера.

#### Разовый URL и обновляемый источник

```http
routing: imsel://routing/onadd/https://example.org/routing.json
```

Эта форма загружает профиль однократно. Для отдельного обновляемого источника
используйте Autorouting:

```http
autorouting: imsel://autorouting/onadd/https://example.org/routing.json
```

Те же ссылки принимаются отдельной строкой смешанного тела, включая Base64,
или через `#routing:` / `#autorouting:`. Сначала выбирается HTTP-источник,
затем тело; внутри источника берётся первое определение, а не последнее.
`://routing/...` и `://autorouting/...` без имени схемы принимаются только
как совместимые маркеры тела подписки, не как системные ссылки для открытия
приложения. Для публикации используйте каноническое `imsel://`.

`add` только добавляет или обновляет профиль; `onadd` также назначает его своей
подписке. Это не команда запуска VPN и не смена профиля приложения. Источник
Autorouting по умолчанию проверяется раз в 24 часа; локальный интервал
`0`/`12`/`24`/`72`/`168` часов относится только к этому профилю и не сбрасывается
определением провайдера. `0` выключает автопроверки, оставляя ручное обновление.
Расписание источника, GeoIP/GeoSite и подписки независимы. URL источника не
включается в экспорт статического пользовательского профиля. Ограничения
публичного HTTP(S), TLS, перенаправлений и размера ответа описаны в
[руководстве](../faq/routing-profiles.md#профиль-по-url-и-autorouting).

### Геобазы профиля подписки

Эти команды изменяют **только собственный профиль обновляемой подписки**.
Они не меняют стандартный профиль, общий профиль приложения, самостоятельный
профиль пользователя или профиль соседней подписки. При необходимости
создаётся отдельный профиль подписки. Если профиль для группы ещё не выбран,
новый профиль назначается ей. Ранее сохранённый выбор другого профиля или явная
команда выбора, включая стандартный профиль, приоритетнее автоматического
назначения этими GEO-командами. Выбранный пользовательский или стандартный
профиль не становится целью этих команд.

| HTTP-заголовок / имя команды тела | Формат |
| --- | --- |
| `routing-geoip-url` | Непустой HTTP(S)-адрес файла GeoIP |
| `routing-geosite-url` | Непустой HTTP(S)-адрес файла GeoSite |
| `routing-geoip-sha256-url` | HTTP(S)-адрес контрольной суммы GeoIP; пустое значение явно убирает адрес суммы |
| `routing-geosite-sha256-url` | HTTP(S)-адрес контрольной суммы GeoSite; пустое значение явно убирает адрес суммы |
| `routing-geo-update-interval` | Целое число часов от `0` до `8760`; `0` выключает автоматические проверки геобаз |

URL передаются без логина, пароля, пробелов и фрагмента `#`; явно указанный порт
должен быть от `1` до `65535`. Отсутствующая команда
сохраняет прежнее значение. Некорректный адрес или интервал игнорируется, а не
заменяет сохранённое значение. Для одного имени **HTTP-заголовок приоритетнее
команды тела даже при некорректном значении**: тело не используется вместо него.
Число передаётся десятичными цифрами без знака и дробной части; логические
значения не являются интервалом.

Пример заголовков:

```http
routing-geoip-url: https://geo.example.org/geoip.dat
routing-geosite-url: https://geo.example.org/geosite.dat
routing-geoip-sha256-url: https://geo.example.org/geoip.dat.sha256
routing-geosite-sha256-url: https://geo.example.org/geosite.dat.sha256
routing-geo-update-interval: 24
```

Те же команды допустимы в теле, если соответствующий HTTP-заголовок отсутствует:

```text
#routing-geoip-url: https://geo.example.org/geoip.dat
#routing-geosite-url: https://geo.example.org/geosite.dat
#routing-geoip-sha256-url: https://geo.example.org/geoip.dat.sha256
#routing-geosite-sha256-url: https://geo.example.org/geosite.dat.sha256
#routing-geo-update-interval: 24
vless://...
```

Без адреса контрольной суммы используется обычная загрузка файла с проверкой
структуры; `.sha256` к адресу автоматически не добавляется. Пустой заголовок
`routing-geoip-sha256-url:` или `routing-geosite-sha256-url:` явно возвращает
такой режим для соответствующего файла, но не отключает проверку структуры.

При заданном URL сначала запрашивается SHA256. Ответ должен быть UTF-8 текстом
не более **64 КиБ**: либо единственная шестнадцатеричная сумма из 64 символов,
либо строки формата `sha256sum` с именем `geoip.dat` или `geosite.dat`
соответственно (`<сумма>  geoip.dat` или `<сумма> *geoip.dat`). Строки других
файлов не используются; противоречащие друг другу суммы нужного файла отклоняются.
Недоступный или некорректный ответ не разрешает загрузку без суммы.

Если полная проверенная локальная копия совпадает с полученной суммой, запрос
файла `.dat` не выполняется. Иначе файл скачивается и устанавливается только
после совпадения SHA256 и проверки структуры. Повторная принудительная загрузка
не обходит эти проверки. При ошибке существующая копия этого источника не
заменяется. Контрольная сумма с того же сервера не является цифровой подписью
и не доказывает подлинность источника.

Интервал провайдера уступает локальному интервалу **этого профиля**; при
отсутствии обоих используется **24 часа**. Следующее обновление метаданных не
стирает локальный выбор, включая `0`. Пользователь может сбросить его к значению
провайдера/по умолчанию при отсутствии блокировки настроек и выбора профиля.
Проверки выполняются при обычной работе приложения по наступлении срока, а не
по точному будильнику. История проверок и загрузок различается для каждого
профиля, файла и источника. Подробнее: [геобазы и интервалы](../faq/routing-profiles.md#загрузка-и-проверка-геобаз).

### Автоподключение

```http
subscription-autoconnect: 1
subscription-autoconnect-type: lastused
```

Автоматическое подключение при запуске приложения (один раз за холодный старт,
если VPN не активен). Критерий выбора сервера: `lastused` (по умолчанию; ранее
выбранный сервер), `lowestdelay` (минимальная доступная задержка среди серверов
этой подписки), `random`.

При включённом автоподключении `lowestdelay` перед новым подключением обязательно
проверяет доступные для текущей сети серверы выбранной URL-подписки. Проверка
использует её актуальные метод, URL и параллельность и не зависит от обычного
автопинга после обновления, включая собственное `subscription-auto-ping-enable: 0`.
Выбор минимальной успешной задержки выполняется после завершения проверки,
а не по частичному результату через 30 секунд. Защитный предел одной стартовой
попытки — **120 секунд**. При таймауте или отсутствии успешных измерений
автоподключение не выполняется: старые результаты, последний или первый сервер
не служат запасным вариантом для этой проверки.

При переходе URL-подписки в сочетание `subscription-autoconnect: 1` и
`subscription-autoconnect-type: lowestdelay` обычный автопинг после обновления
по умолчанию выключается только для неё, если его настройка не заблокирована.
Глобальное значение и соседние подписки не меняются. Пока это сочетание включено,
обычный автопинг после обновления не выполняется, а пользовательский тумблер
выключен и недоступен. Ограничение не перезаписывает заблокированное значение
и не отменяет обязательную стартовую проверку. После выхода из режима
редактирование снова доступно с учётом точечных, общих, ручных и авторских
блокировок; ранее изменённое значение автоматически не восстанавливается.
Стартовая проверка и обычный автопинг после начального обновления не создают
два одинаковых прохода.

Уже активный VPN не останавливается, не сканируется и не переключается ради
стартового выбора. Новая обязательная массовая проверка не вводится для локальных
групп без URL; исключение локальных групп из обычного автопинга сохраняется.
Если подготовка закончилась в фоне, подключение откладывается до возвращения
приложения на экран. Ручной выбор сервера, подключение, Stop проверки или обновления,
остановка VPN, изменение настроек проверки, смена сети, замена или удаление
выбранной подписки отменяют
отложенное стартовое подключение: оно не должно переиграть действие пользователя.
Поздние ответы отменённой проверки не возобновляют подключение.

Пользователь меняет включение и критерий независимо, если соответствующее поле не заблокировано. Оба поля допускают точечную, общую и ручную блокировку. Выключение автоподключения не стирает критерий; в UI выбор критерия показывается при включённом автоподключении.

### Скрытие и сворачивание подписки

```http
subscriptions-hide-enable: 1
```

Карточка подписки по умолчанию **всегда раскрыта** (список серверов виден, тап по шапке не сворачивает). Порядок приоритетов:

1. **Локальный тумблер «Сворачивание списка серверов»** (экран «Настройки подключения», раздел «Соединение») — включён: сворачивание/раскрытие по тапу работает для всех подписок, включая панельные (приоритетнее заголовка);
2. **Заголовок `subscriptions-hide-enable: 1`** (per-sub, тринарно): разрешает сворачивание этой подписки по тапу;
3. **Всегда**: сворачивание/раскрытие работает для ручных серверов и импорта из буфера — независимо от тумблера и заголовка.

Тумблер «Скрыт с главного» расположен под настройкой сворачивания, но меняет видимость всей подписки. Для него поддерживается значение `subscription-hidden`, а `subscription-lock-hidden` игнорируется. Ни общий замок провайдера, ни `hide-settings` не запрещают пользователю менять скрытие. Ручная блокировка и ограничения автора раздачи сохраняются. Пользовательское скрытие также недоступно, если подписка в приложении всего одна: главный экран опустел бы.

Само разрешение сворачивания допускает точечный `subscription-lock-server-list-collapse`, общий замок и режим защиты провайдера. Если список остаётся раскрытым из-за такого ограничения, можно скрыть подписку целиком, когда это доступно.

#### Совместимое имя сворачивания

```http
subscriptions-collapse: false
```

`subscriptions-collapse` выключает (`false`/`0`) или включает (`true`/`1`) разрешение сворачивать список **только этой подписки**. Общий переключатель приложения не меняется. Если задан корректный `subscriptions-hide-enable`, используется он; `subscriptions-collapse` служит совместимым вариантом. Отсутствующее или некорректное значение сохраняет прежний выбор.

После обновления пользователь может изменить этот выбор, если нет соответствующих блокировок. Сворачивание не входит в исключения провайдера. Принимается и строка тела: `#subscriptions-collapse: false`. В старых версиях команда могла менять общий переключатель; описанное здесь действие относится к текущему поведению для одной подписки.

### Автопинг серверов подписки

```http
subscription-auto-ping-enable: 1
```

Значение `1` или `true` включает обычную автоматическую проверку задержки доступных для текущей сети серверов **только этой подписки с URL** после её успешного непустого обновления. Значение `0` или `false` выключает её. Проверка выполняется как delay-пинг выбранным для подписки методом (см. ниже). Само открытие приложения не запускает её без нового lowestdelay-автоподключения. Обязательная свежая проверка перед таким подключением независима от этого значения и описана выше. В локальных группах без URL массового автопинга нет, в том числе при импорте; ручные проверки остаются доступны.

Успешное непустое обновление сбрасывает прежние результаты пинга всех серверов
только обновлённой подписки, включая неизменившиеся и скрытые сетевым фильтром.
Соседние подписки не затрагиваются. Скрытые серверы не проверяются, пока скрыты.
Поздние ответы начатых до обновления проверок не восстанавливают старые результаты.
Ошибка, пустой список или отмена до завершения обновления сохраняют прежние
результаты; Stop после завершения не отменяет сброс. Сброс не включает автопинг.

В карточке подписки доступен один тумблер «Автопинг серверов». Тумблер и заголовок управляют одной настройкой: последнее действие пользователя или полученный заголовок задаёт собственное включение/выключение этой подписки. Оба значения приоритетнее глобального переключателя приложения; настройки других подписок не влияют на решение.

Глобальный переключатель «Автопинг после обновления подписок» применяется только к подпискам, для которых собственное значение ещё не задано. До первого собственного выбора тумблер отображает действующее значение. Отсутствие заголовка при обновлении не сбрасывает сохранённую настройку.

При открытии приложения с уже работающим VPN одиночная проверка относится
только к достоверно определённому активному серверу, если его конфигурация
в списке соответствует работающему подключению. Если соответствие неизвестно
или конфигурация уже изменилась, проверка не подменяет её другой записью
или новой версией; обновление пинга в таком случае не гарантируется.

После подключения, переключения на другой сервер или переподключения задержка
проверяется заново, даже если прежний результат уже есть. Единственное
исключение: после успешного стартового подключения URL-подписки по критерию
«Минимальная задержка» со свежей завершённой проверкой дополнительный одиночный
пинг сразу после подтверждения подключения пропускается. Это исключение
не отменяет проверки после других способов стартового выбора, ручного
подключения, переключения, переподключения или последующего открытия
приложения с активным VPN и соответствующей конфигурацией.

Эти одиночные проверки не зависят от тумблера подписки, заголовка или глобального
переключателя. При выключенном VPN само открытие приложения без нового
lowestdelay-автоподключения не запускает пинг выбранного сервера.

Совместимое имя `subscription-ping-onopen-enabled` поддерживается с тем же смыслом. HTTP-заголовки имеют приоритет над командами `#param` тела подписки; если один источник содержит оба имени, используется `subscription-auto-ping-enable`.

Например, при включённом глобальном автопинге явное `subscription-auto-ping-enable: 0` выключит проверку подписки A, но не изменит подписку B. При выключенном глобальном автопинге явное `1` включит проверку только подписки A.

### Метод, URL и параллельность проверки задержки

Для ручной проверки кнопка задержки на карточке подписки использует выбранный метод. Команда TCP-пинга в меню подписки запускает отдельную прямую TCP-проверку независимо от выбранного метода.

| Заголовок ответа | Допустимое значение | Назначение |
| --- | --- | --- |
| `ping-type` | `proxy`, `proxy-head`, `tcp`, `icmp` | Собственный метод проверки задержки этой подписки: HTTP GET через прокси, HTTP HEAD через прокси, прямой TCP или прямой ICMP соответственно |
| `check-url-via-proxy` | URL со схемой `http://` или `https://` | Собственный адрес проверки для `proxy` и `proxy-head`; не влияет на прямые TCP/ICMP-проверки |
| `subscription-ping-batch-size` | Целое число **1–25** | Количество одновременных проверок delay-пинга **выбранным методом**, включая `tcp` и `icmp` |
| `subscription-tcp-ping-batch-size` | Целое число **1–25** | Количество одновременных проверок **только отдельной команды TCP-пинга**; не управляет delay-пингом, даже если его метод `tcp` или `icmp` |

Эти параметры задают собственные настройки одной подписки. Они доступны пользователю в настройках задержки группы. Пустое числовое поле означает использование соответствующего лимита приложения; для метода и URL есть отдельный выбор настроек приложения. Собственное число заменяет значение приложения по умолчанию для этой подписки, а не ограничивается им. Например, число для подписки A не меняет проверки подписки B. При общей проверке всех подписок дополнительно действует общий лимит приложения для соответствующей проверки.

В боковом меню «Пинг» задаются настройки приложения: метод, URL и параллельность. Лимит delay-пинга: 1–25 (по умолчанию 6), отдельного TCP-пинга: 1–25 (по умолчанию 15). **Предупреждение:** высокая параллельность увеличивает нагрузку на процессор, память и сеть, но не повышает точность измерений. Она повышает риск ложных ошибок при проверке доступных серверов; при сомнениях уменьшите число и повторите проверку.

HTTP-заголовок имеет приоритет над одноимённой командой `#param` в теле подписки. Отсутствующее или некорректное значение не сбрасывает сохранённый выбор. Если HTTP-заголовок присутствует, но некорректен, команда из тела вместо него не применяется. Корректное полученное значение сохраняется только для обновляемой подписки и действует для последующих проверок, включая автопинг после этого успешного обновления. Блокировка настроек запрещает пользователю менять эти поля, но провайдер может задавать их заголовками.

Пример HTTP-заголовков:

```http
ping-type: icmp
subscription-ping-batch-size: 4
subscription-tcp-ping-batch-size: 10
```

Delay-пинг этой подписки выполняет до **4 одновременных ICMP-проверок**. Число `10` относится только к отдельной команде TCP-пинга и не меняет параллельность ICMP.

Те же настройки можно передать в теле подписки, если соответствующих HTTP-заголовков нет:

```text
#ping-type: icmp
#subscription-ping-batch-size: 4
#subscription-tcp-ping-batch-size: 10
vless://...
```

Для проверки HTTP HEAD через прокси используйте `ping-type: proxy-head` и, например, `check-url-via-proxy: https://example.com/`. Метод `proxy` проверит тот же URL запросом GET. Подробнее о пользовательских полях: [частые вопросы о проверке задержки](../faq/subscription-updates.md#частые-вопросы).

### Sniffing (per-subscription)

```http
sniffing-enable: 1
```

Анализ трафика (sniffing) задаётся отдельно для серверов **этой подписки**. В панели управления подпиской рядом с «Настройками подключения» есть кнопка «Sniffing»: окно с тремя переключателями — Sniffing / routeOnly / metadataOnly. Команда `sniffing-enable` управляет включением Sniffing: `1` — включить, `0` — выключить, отсутствие — не менять.

**JSON-подписки:** настройки Sniffing доступны и для групп, состоящих только из JSON. По умолчанию готовые JSON сохраняют собственный Sniffing. Значения карточки, включая явное выключение и явно заданные списки, применяются только после собственного разрешения пользователя «Применять настройки к JSON» в Sniffing этой группы. В URL-подписках такое разрешение тоже доступно. Заголовки не включают его; его замок поддерживается отдельно. Исходный JSON не перезаписывается. Подробнее: [Sniffing и списки](../faq/getting-started.md#6-сниффинг-и-списки-для-одной-группы).

### Автообновление (per-subscription)

```http
subscription-auto-update-enable: 0
subscription-auto-update-open-enable: 1
```

Управляют тумблерами карточки **этой** подписки (эко-система):

- `subscription-auto-update-enable` — «Автообновление» (интервальное, 1–168 ч; интервал сохраняется, `profile-update-interval` может задать свой). `0` — выключить, `1` — включить.
  *Отложенное фоновое обновление:* Если по какой-то причине фоновое обновление не смогло выполниться (например, на устройстве был отключён интернет или ОС заблокировала фоновую задачу), обновление откладывается. При следующем заходе (открытии) в приложение пропущенное обновление будет запущено автоматически. Важно: подписка, скрытая с главного экрана, при открытии приложения автоматически не обновляется — отложенное обновление дождётся следующего фонового окна расписания (фоновое расписание скрытые подписки не исключает) либо ручного обновления.
- `subscription-auto-update-open-enable` — «Обновление при открытии»: принудительно обновлять эту подписку при **каждом** открытии приложения, независимо от интервала. Что считается открытием: запуск приложения и возврат в него после длительного сворачивания; кратковременные прерывания (шторка уведомлений, системный диалог, переключение на другое приложение на пару секунд) новым открытием **не** считаются. Подписка, скрытая с главного экрана, при открытии не обновляется (ручное обновление из меню подписки остаётся доступным); фоновое интервальное обновление скрытой подписки продолжается по расписанию.

Оба тумблера доступны в окне управления подпиской («Ещё»), если на соответствующее поле не действует замок. Команда и UI управляют одной настройкой этой подписки; замок не запрещает провайдеру прислать новое значение.

### Неотключаемый HWID

```http
subscription-always-hwid-enable: 1
```

Принимается и сохраняется. В IMSEL `X-HWID` отправляется всегда (выключателя в приложении нет), поэтому команда фактически закрепляет существующее поведение.

### Лимиты памяти ядра

```http
no-limit-enabled: 1
```

Команда пока не меняет работу приложения. Не следует рассчитывать на неё как на способ устранения нехватки памяти.

## Описание сервера (serverDescription)

Подпись под именем сервера (вместо технического тега «VLESS / WS / TLS»). Добавляется в фрагмент share-ссылки после имени:

```text
vless://uuid@server:443#IMSEL-Node?serverDescription=SVB2NiBPbmx5
```

Значение — base64 (при невозможности декодирования принимается как plain text). Рекомендуемая длина — до 30 символов. Поддерживается во всех форматах ссылок (vless/vmess/trojan/ss/socks/wireguard/hysteria2) и в JSON-подписках через поле `meta.serverDescription`.

## Время действия параметров

Заголовки имеют приоритет над `#param`-строками. Отсутствующие команды не меняют выбор пользователя.

Данные подписки, баннеры, настройки и замки обновляются при успешном получении подписки. Изменённые URL, таймаут и User-Agent используются для следующих запросов. Сохранённые значения и замки переживают перезапуск; прекращение отправки команды не снимает ранее полученный замок. Исключение из сохранения разрешений: право просмотра конфигов через `hide-settings: 0` нужно подтверждать в каждом успешном ответе, как описано в разделе защиты.

## Не поддерживается

- `routing: 1/0`, `autorouting: 1/0`, `routing-enable` не поддерживаются как переключатели маршрутизации; ссылки профиля и обновляемого источника имеют отдельные форматы, описанные выше;
- `per-app-proxy-enable/-mode/-list`, `app-auto-start` — платформо-зависимые (Android) параметры;
- `socks-auth-*`, `http-auth-*`, `tun-type`, `custom-tunnel-config` — desktop-параметры;
- `no-limit-enabled` — сохраняется, но не меняет работу приложения;
- Provider ID / Premium API (Lite Mode, кастомные темы, баннеры, push) — не реализовано.

Настройки одного сервера в его имени описаны в отдельном справочнике:

подписку и имеют собственные правила приоритета и удаления при обновлении.
